# 04. On-Page SEO & Search Snippets Audit

On-page SEO is the process of improving individual pages so that search engines and visitors can understand their purpose, relevance, structure, and value.

A strong on-page audit goes beyond adding keywords to titles and headings. It evaluates how well each page satisfies its intended search intent, communicates its subject, supports navigation, and presents useful information.

This section covers page-level optimization for traditional search, featured snippets, answer engines, and AI-assisted discovery.

> **Important:** There is no universal keyword-density formula, mandatory title-tag character limit, or requirement to use exactly one H1 heading on every page. Search engines may also rewrite title links and generate snippets from page content.

---

## 1. Page Purpose & Search Intent

### 1.1 Confirm the primary purpose of each page

- [ ] Every important page has a clearly defined purpose.
- [ ] The page targets a relevant audience and user need.
- [ ] Its content matches the expected search intent.
- [ ] The page provides a clear next step where appropriate.
- [ ] Similar pages do not compete unnecessarily for the same search intent.

**Why it matters:** A page should satisfy the reason someone visited it. A page targeting informational intent should not behave like a thin sales landing page.

**How to audit:**

1. Identify the primary query or topic for the page.
2. Review the current search results for that query.
3. Identify whether the dominant intent is informational, commercial, transactional, or navigational.
4. Compare the page's content, format, and purpose with that intent.
5. Identify missing information or unnecessary content.

**Example:**

A page targeting "best website hosting for beginners" should help users compare hosting options, understand important features, and make an informed decision. A page containing only an affiliate purchase button is unlikely to satisfy the full intent.

### 1.2 Assign a primary topic and supporting subtopics

- [ ] Each page has one clear primary topic.
- [ ] Supporting topics are relevant to the main subject.
- [ ] Important related questions are addressed where useful.
- [ ] The page does not target unrelated keywords simply to increase traffic.
- [ ] Content overlaps with other pages are reviewed.

**How to audit:**

Create a simple page-to-topic mapping:

| Page | Primary topic | Supporting topics |
|---|---|---|
| Hosting guide | Web hosting for beginners | Hosting types, pricing, performance |
| Pricing page | Website development pricing | Packages, deliverables, timelines |
| Service page | WordPress development | Customization, maintenance, support |

## 2. Title Tags & Search Title Links

### 2.1 Review title tags

- [ ] Every important indexable page has a descriptive title tag.
- [ ] The title accurately represents the page content.
- [ ] The primary topic appears naturally and prominently.
- [ ] Titles are unique across important pages.
- [ ] Titles avoid unnecessary keyword repetition.
- [ ] Brand names are included where they add useful context.
- [ ] Titles are not misleading or excessively promotional.

**Why it matters:** Title elements help search engines and users understand a page. They can influence how a page's title link appears in search results.

**How to audit:**

- Inspect the page source or SEO tool output.
- Compare the title with the actual page content.
- Check Google Search Console for queries and pages with impressions.
- Review whether the title communicates a useful reason to visit.

**Example:**

Weak: `SEO Services | SEO Company | Best SEO | SEO Experts`

Better: `SEO Services for Small Businesses | Company Name`

### 2.2 Avoid fixed character-count assumptions

- [ ] Titles communicate the main topic without unnecessary wording.
- [ ] Important information appears early when practical.
- [ ] Titles are reviewed in actual search-result previews where possible.
- [ ] The team understands that search engines may truncate or rewrite title links.

There is no guaranteed character limit that ensures a title will display exactly as written. Display depends on available space, device, query, and search engine decisions.

**Recommended approach:** Prioritize clarity, relevance, uniqueness, and usefulness over hitting an arbitrary character count.

### 2.3 Review title consistency

- [ ] Important pages use consistent naming conventions.
- [ ] Category and product titles are distinguishable.
- [ ] Location pages clearly identify their service area.
- [ ] Blog titles accurately represent article content.
- [ ] Automatically generated titles are checked for duplication and errors.

## 3. Meta Descriptions & Search Snippets

### 3.1 Review meta descriptions

- [ ] Important pages have useful meta descriptions where appropriate.
- [ ] Descriptions summarize the actual page content.
- [ ] Each description is sufficiently distinct.
- [ ] Relevant user benefits or page details are communicated.
- [ ] Calls to action are natural and not misleading.
- [ ] Keyword stuffing and repetitive wording are avoided.

**Why it matters:** Meta descriptions may be used as search-result snippets. They can help users decide whether a result is relevant, although Google may generate a different snippet from page content.

**Example:**

Weak: `We provide the best services. Contact us today for more information.`

Better: `Explore professional WordPress website development services, including custom design, responsive layouts, and business-focused website solutions.`

### 3.2 Understand snippet generation

- [ ] The page contains useful introductory information.
- [ ] Important answers are clearly explained in the visible content.
- [ ] Key information is not hidden exclusively inside inaccessible elements.
- [ ] Search snippets are reviewed against actual queries where possible.
- [ ] The team understands that snippets are not fully controlled by meta descriptions.

**Important:** A search engine can select different page text for different queries. A well-written meta description does not guarantee that it will appear.

### 3.3 Review snippet performance

- [ ] Search Console queries are reviewed for important pages.
- [ ] Pages with high impressions and weak CTR are investigated.
- [ ] Title and description relevance is compared with the query.
- [ ] Changes are tested and monitored over time.
- [ ] CTR is interpreted alongside ranking position, device, search appearance, and query intent.

Do not assume every low-CTR page needs a rewritten title. The search intent, ranking position, competition, and SERP features may be responsible.

## 4. Headings & Content Hierarchy

### 4.1 Review heading structure

- [ ] Headings describe the sections that follow.
- [ ] The page has a clear and understandable content hierarchy.
- [ ] Important sections are easy to identify.
- [ ] Heading levels are used meaningfully.
- [ ] Headings are not used only to create visual styling.
- [ ] Repeated or irrelevant headings are removed.

**Why it matters:** Headings help readers navigate content and help systems understand its organization.

**Important:** One H1 per page is a useful editorial convention, but it is not a universal Google ranking requirement. Focus on a logical, accessible structure rather than treating the number of H1 elements as a ranking formula.

### 4.2 Check heading relevance

- [ ] The main heading communicates the page's subject.
- [ ] Supporting headings cover relevant subtopics.
- [ ] Questions are used as headings where they improve navigation.
- [ ] Headings are descriptive rather than artificially keyword-heavy.
- [ ] Headings do not promise information that the section fails to provide.

**Example:**

Main heading: `How to Choose a Web Hosting Provider`

Supporting headings:
- `Understand Your Hosting Requirements`
- `Compare Server Performance`
- `Review Pricing and Renewal Costs`
- `Check Support and Backup Options`

### 4.3 Improve scannability

- [ ] Long content is divided into meaningful sections.
- [ ] Lists and tables are used where they improve comprehension.
- [ ] Important information is easy to find.
- [ ] Paragraphs are readable on mobile screens.
- [ ] Complex instructions are presented in logical steps.

## 5. Keyword Placement & Contextual Relevance

### 5.1 Use natural language

- [ ] The primary topic is clearly communicated.
- [ ] Relevant terms appear naturally in appropriate sections.
- [ ] Related concepts are covered where they help the reader.
- [ ] Exact-match phrases are not forced into every section.
- [ ] Repetitive keyword variations are removed.
- [ ] Content is written for people rather than a keyword-density target.

**Why it matters:** Search systems need to understand what a page is about, but repeating the same keyword does not automatically make a page more relevant.

### 5.2 Review important page elements

Check whether the main topic is naturally reflected in:

- [ ] Title tag
- [ ] Main page heading
- [ ] Introduction
- [ ] Relevant subheadings
- [ ] Descriptive URL
- [ ] Image context and alternative text, where appropriate
- [ ] Internal link anchor text, where relevant

Not every keyword needs to appear in every element.

### 5.3 Avoid keyword cannibalization

- [ ] Multiple pages targeting similar queries are reviewed.
- [ ] Pages with overlapping intent have distinct purposes.
- [ ] Content consolidation is considered when pages are genuinely redundant.
- [ ] Internal links help communicate the relationship between related pages.
- [ ] Separate pages are retained when they serve meaningfully different needs.

**How to audit:**

Use Google Search Console to identify cases where multiple URLs receive impressions for the same query. Investigate whether this represents genuine competition or simply useful coverage of related search needs.

## 6. URL Structure & Page Slugs

### 6.1 Review page URLs

- [ ] URLs are descriptive and understandable.
- [ ] Slugs represent the page topic.
- [ ] Unnecessary parameters and confusing URL variations are reviewed.
- [ ] URLs avoid excessive nesting where practical.
- [ ] Important pages use consistent URL conventions.
- [ ] URLs are not changed without a migration and redirect plan.

**Example:**

Less descriptive:

`example.com/page?id=8274`

More descriptive:

`example.com/wordpress-development/`

### 6.2 Review URL readability

- [ ] Words are separated with hyphens where appropriate.
- [ ] Unnecessary dates, IDs, and tracking parameters are avoided in canonical URLs.
- [ ] URLs are not excessively long without a reason.
- [ ] Lowercase conventions are applied consistently where appropriate.
- [ ] Existing indexed URLs are protected from unnecessary changes.

**Important:** Short URLs are not automatically better. A clear, stable URL is more useful than a short but confusing one.

### 6.3 Check URL changes

If a URL must change:

- [ ] Map the old URL to the most relevant new destination.
- [ ] Implement an appropriate permanent redirect when applicable.
- [ ] Update internal links.
- [ ] Update canonical references.
- [ ] Update XML sitemap entries.
- [ ] Monitor indexing, traffic, and redirect errors after deployment.

See the Technical SEO & Crawlability audit for deeper redirect and canonical checks.

## 7. Images & Visual Content SEO

### 7.1 Review image relevance

- [ ] Images support the surrounding content.
- [ ] Important images are relevant and useful.
- [ ] Decorative images do not distract from the main purpose.
- [ ] Images are not used as a substitute for essential text.
- [ ] Image placement supports the user's understanding.

### 7.2 Review alternative text

- [ ] Informative images have meaningful alt text.
- [ ] Alt text communicates the image's purpose or relevant information.
- [ ] Decorative images use an appropriate empty alt attribute where applicable.
- [ ] Alt text avoids keyword stuffing.
- [ ] Complex charts and diagrams have their key information available in text.
- [ ] Product images describe useful product details where appropriate.

**Example:**

Weak: `SEO SEO services best SEO company`

Better: `Website performance report showing page speed measurements`

**Important:** Alt text is primarily an accessibility feature. It should describe the image's relevant information, not act as a keyword insertion field.

### 7.3 Review image filenames and formats

- [ ] Image filenames are understandable where practical.
- [ ] Appropriate modern image formats are considered.
- [ ] Images are compressed without unacceptable quality loss.
- [ ] Responsive image sizes are provided where appropriate.
- [ ] Image dimensions are specified to help reduce layout shifts.
- [ ] Lazy loading is applied appropriately without delaying critical above-the-fold images.

See the Performance & Core Web Vitals audit for deeper image-loading checks.

### 7.4 Review image discovery

- [ ] Important images are discoverable by search engines.
- [ ] Images are not unnecessarily blocked from crawling.
- [ ] Image sitemap use is considered for relevant websites.
- [ ] Image captions and surrounding text provide useful context where appropriate.

## 8. Internal & External Linking

### 8.1 Review internal links

- [ ] Important pages receive relevant internal links.
- [ ] Links help users discover related information.
- [ ] Important pages are not isolated without a good reason.
- [ ] Anchor text describes the destination.
- [ ] Links are not inserted only to increase link counts.
- [ ] Navigation links are consistent and usable.

**Example:**

Weak anchor: `Click here`

Better anchor: `Read our WordPress website development guide`

### 8.2 Review contextual linking

- [ ] Related articles link to relevant service or category pages.
- [ ] Supporting content points to useful primary resources.
- [ ] Links appear where users may naturally need additional information.
- [ ] Links do not interrupt reading unnecessarily.
- [ ] Important destinations can be reached through crawlable links.

### 8.3 Review external links

- [ ] External sources are relevant and trustworthy.
- [ ] References support factual or technical claims.
- [ ] Links are checked for broken destinations.
- [ ] Paid or sponsored links use appropriate link attributes.
- [ ] Affiliate relationships are disclosed clearly where required.

External links should be added because they help the reader, not because of an assumed ranking benefit.

### 8.4 Review link attributes

- [ ] Sponsored links use appropriate `rel="sponsored"` attributes where applicable.
- [ ] User-generated links are handled appropriately.
- [ ] `nofollow` is used where justified.
- [ ] Link attributes are not applied indiscriminately to all internal links.

## 9. Structured Data & Rich Result Eligibility

Structured data can help eligible search engines understand specific page entities and information. It does not guarantee rich results or higher rankings.

### 9.1 Review structured data relevance

- [ ] Structured data matches the visible page content.
- [ ] The selected schema type accurately represents the page.
- [ ] Required and recommended properties are reviewed against current documentation.
- [ ] Structured data does not contain fabricated information.
- [ ] Important properties are kept up to date.

Common relevant types may include:

- Organization
- LocalBusiness
- Article
- Product
- BreadcrumbList
- Event
- Recipe
- VideoObject

Only implement types that accurately describe the page and meet the applicable guidelines.

### 9.2 Validate implementation

- [ ] Relevant structured data is tested using Google's Rich Results Test.
- [ ] Schema.org Validator is used for broader vocabulary validation where helpful.
- [ ] Search Console enhancement reports are reviewed where available.
- [ ] Errors and warnings are investigated.
- [ ] Structured data is rechecked after template or content changes.

### 9.3 Avoid common schema mistakes

- [ ] No misleading ratings or reviews are marked up.
- [ ] Hidden or unrelated content is not represented as visible page content.
- [ ] Product prices and availability are accurate.
- [ ] Business details match the actual business.
- [ ] Duplicate or conflicting schema entities are reviewed.

**Important:** Valid structured data means the implementation meets technical requirements. It does not guarantee that Google will display a rich result.

---

## 10. Social Sharing & Link Previews

Social preview metadata helps control how a page may appear when shared on supported platforms. It should not be confused with a guaranteed Google ranking factor.

### 10.1 Review Open Graph metadata

- [ ] Important pages have an appropriate Open Graph title.
- [ ] Open Graph description accurately summarizes the page.
- [ ] A relevant sharing image is configured.
- [ ] Image dimensions and accessibility are reviewed.
- [ ] The canonical page URL is represented correctly.
- [ ] Preview metadata is consistent with the actual page.

Common properties include:

- `og:title`
- `og:description`
- `og:image`
- `og:url`
- `og:type`

### 10.2 Review platform-specific previews

- [ ] Platform-specific metadata is implemented where required.
- [ ] Preview images are accessible to the relevant platforms.
- [ ] Shared URLs display the correct title and description.
- [ ] Social preview tools are used to troubleshoot unexpected results.

Do not assume that every platform uses the same metadata or displays every property identically.

## 11. Page Templates & Special Page Types

Different page types need different optimization checks. Do not apply the same checklist blindly to every URL.

### 11.1 Blog and editorial pages

- [ ] Article purpose and intended audience are clear.
- [ ] Author information is accurate where relevant.
- [ ] Publication and update dates are meaningful and accurate.
- [ ] Sources support important claims.
- [ ] Editorial content provides original value.
- [ ] Related articles are linked where useful.
- [ ] Article structured data is accurate where applicable.

### 11.2 Service and landing pages

- [ ] The service and target audience are clear.
- [ ] Deliverables and limitations are explained.
- [ ] Benefits are supported by credible information.
- [ ] Pricing or enquiry expectations are clear where relevant.
- [ ] Trust signals are genuine.
- [ ] Calls to action are visible and understandable.
- [ ] The page avoids unsupported guarantees.

### 11.3 Ecommerce product pages

- [ ] Product names and descriptions are unique and useful.
- [ ] Price and availability information is accurate.
- [ ] Product images show the actual product.
- [ ] Important specifications are available in text.
- [ ] Variants and options are understandable.
- [ ] Shipping, returns, and warranty information is accessible.
- [ ] Product structured data and merchant information are accurate where applicable.
- [ ] Duplicate product URLs and filter variations are reviewed.

### 11.4 Category and collection pages

- [ ] Category purpose is clear.
- [ ] Introductory content helps users understand the collection.
- [ ] Product or content listings are accessible.
- [ ] Filters and sorting do not create uncontrolled URL duplication.
- [ ] Pagination is handled consistently.
- [ ] Important category pages have useful internal links.

### 11.5 Location and local service pages

- [ ] The actual service area is represented accurately.
- [ ] Business details are consistent with reality.
- [ ] Location-specific content provides genuine value.
- [ ] Pages are not mass-produced by replacing city names.
- [ ] LocalBusiness structured data is accurate where applicable.
- [ ] Contact and location information is easy to find.

## 12. AI Search, Answer Engines & On-Page Readability

AI search systems and answer engines may use page content to understand topics and generate responses. There is no guaranteed method to make a page appear in AI-generated answers.

Google's guidance for AI features emphasizes established Search fundamentals rather than a separate set of special technical requirements.

### 12.1 Make important information understandable

- [ ] The page clearly identifies its subject.
- [ ] Important concepts are explained in direct language.
- [ ] Definitions are included where they genuinely help.
- [ ] Relevant questions are answered within the appropriate sections.
- [ ] Important facts are supported by credible sources.
- [ ] Ambiguous statements are clarified.

### 12.2 Improve answer usefulness

- [ ] Direct answers are provided where the topic calls for them.
- [ ] Supporting explanation follows the answer.
- [ ] Comparisons use clear criteria.
- [ ] Processes are explained in logical steps.
- [ ] Tables are used when they make comparisons easier.
- [ ] Content provides original examples, experience, or useful analysis.

### 12.3 Maintain source quality and context

- [ ] Important claims have identifiable sources.
- [ ] Statistics include relevant dates and context.
- [ ] Opinions are distinguishable from verified facts.
- [ ] Authors and organizational information are transparent where relevant.
- [ ] Content is reviewed when facts, products, or guidance change.

### 12.4 Avoid unsupported AI optimization tactics

- [ ] No claims are made that a particular schema guarantees AI citations.
- [ ] No artificial keyword repetition is introduced for language models.
- [ ] No fake expert quotations or fabricated statistics are used.
- [ ] No unnecessary FAQ sections are added purely to target AI systems.
- [ ] Content is not rewritten into robotic question-and-answer fragments without a reader benefit.

**Principle:** Optimize for clear, useful, accessible, trustworthy information. Do not treat GEO, AEO, or LLMO as guaranteed ranking or citation formulas.

## 13. Accessibility & Readability

- [ ] Text has sufficient contrast against its background.
- [ ] Font sizes are readable on common devices.
- [ ] Links are distinguishable and descriptive.
- [ ] Form labels are understandable.
- [ ] Images have appropriate text alternatives.
- [ ] Heading structure supports navigation.
- [ ] Important information is not communicated through colour alone.
- [ ] Content remains usable with keyboard navigation.
- [ ] Tables have meaningful headers.
- [ ] Page content is understandable without relying entirely on visual styling.

Accessibility is not merely an SEO technique. It helps more people use the website successfully and should be considered as a core quality requirement.

## 14. On-Page Audit Workflow

Use this workflow to audit an individual page.

1. **Identify the page:** Record its URL, template, purpose, and importance.
2. **Identify the search intent:** Understand the query and user need.
3. **Inspect the search appearance:** Review title, snippet, and competing results.
4. **Inspect the page:** Review headings, content, keywords, images, and links.
5. **Check technical signals:** Review indexability, canonical, and structured data. Refer to the Technical SEO audit for detailed checks.
6. **Review usability:** Check readability, accessibility, mobile presentation, and calls to action.
7. **Check performance data:** Review impressions, clicks, CTR, and conversions where available.
8. **Record evidence:** Capture the issue, affected URL, and supporting data.
9. **Prioritize fixes:** Estimate impact, effort, and risk.
10. **Verify changes:** Recheck the page and monitor results after implementation.

### Suggested page audit record

| Field | Example |
|---|---|
| URL | `example.com/wordpress-development/` |
| Page type | Service page |
| Primary topic | WordPress development |
| Search intent | Commercial |
| Main issue | Generic title tag |
| Evidence | Search Console + page inspection |
| Recommended fix | Rewrite title to reflect service and audience |
| Priority | Medium |
| Owner | SEO / Content team |
| Verification | Recheck rendered page and Search Console |

## 16. Prioritization Framework

Not every on-page issue deserves the same priority.

| Priority | Typical examples |
|---|---|
| Critical | Important page is accidentally noindexed, content is missing, or a major template error prevents intended visibility |
| High | Misleading title, severe intent mismatch, incorrect product information, or major content gaps |
| Medium | Weak headings, poor internal links, duplicate descriptions, or unclear image alternatives |
| Low | Minor wording improvements, optional social preview refinements, or cosmetic metadata consistency |

Consider these factors before assigning priority:

- Business and user impact
- Number and importance of affected pages
- Search performance evidence
- Implementation effort
- Risk of unintended side effects

A technically imperfect description is not automatically more important than a page that fails to answer the visitor's main question.

## 17. Common On-Page SEO Mistakes

Avoid these outdated or misleading practices:

- Treating a fixed keyword density as a ranking requirement.
- Repeating the primary keyword unnaturally.
- Assuming every title must fit a universal character limit.
- Assuming Google always displays the written meta description.
- Treating exactly one H1 as a mandatory ranking rule.
- Writing headings for search engines instead of readers.
- Adding FAQs to every page without a genuine user need.
- Adding schema that does not match visible content.
- Assuming structured data guarantees rich results.
- Writing alt text primarily for keyword insertion.
- Changing established URLs without redirect planning.
- Creating near-identical location pages at scale.
- Measuring success only through keyword positions.
- Treating AI search visibility as a guaranteed outcome of special formatting.

## 18. Completion Criteria

An on-page audit is complete when:

- [ ] Important pages have a defined purpose and intended search intent.
- [ ] Titles and descriptions are reviewed for relevance and accuracy.
- [ ] Headings and content hierarchy are understandable.
- [ ] Keyword use is natural and contextually relevant.
- [ ] URLs are descriptive and stable.
- [ ] Images and alternative text are reviewed.
- [ ] Internal and external links are useful and accurate.
- [ ] Structured data is validated where applicable.
- [ ] Social previews are reviewed where relevant.
- [ ] Specialized page templates are audited appropriately.
- [ ] Accessibility and readability issues are documented.
- [ ] AI-search-related improvements focus on content usefulness and clarity.
- [ ] Issues have evidence, owners, priorities, and recommended fixes.
- [ ] Implemented changes have a verification plan.
